# Research Matching Tool

Discover research and explore how published literature relates to organized experimental findings. This tool assists source discovery and reading; it does not write papers or validate experimental results.

## Run

Requires Node.js 24+. No API keys are required. Startup respects the environment's HTTPS proxy.

```sh
npm ci
npm test
npm run check
npm start
```

The server uses port 3000 (override with `PORT`) and serves the production build generated by `npm test` or `npm run build`. The server requires HTTPS access to `api.crossref.org`, `doaj.org` (optional journal-policy lookup), and `www.ebi.ac.uk` (Europe PMC full-text retrieval).

For frontend development, run `npm start` in one terminal and `npm run dev` in another. Vite proxies API calls to port 3000.

The frontend uses React, Vite, Tailwind CSS, shadcn/ui (buttons, badges, accordions and tabs) and Adobe React Aria Components (radio groups, checkboxes, file selection and modal dialogs). shadcn components are vendored from the official MIT-licensed source; their license is retained in `src/components/ui/LICENSE`.

## Workflow

1. Enter research context and organized findings, optionally importing a text/CSV/TSV file. Describe graphs in text.
2. Find articles using keywords, resource type and date filters, or resolve known DOIs/doi.org URLs.
3. Sort results, select references, compare reported methods and findings with the experiment, or select a pair for a side-by-side article comparison. DOI mode automatically displays summaries and experiment comparisons.

Article-card summaries are publisher-deposited abstract extracts, capped at 1,000 characters. Missing abstracts are explicitly identified. Comparisons retrieve open-access full-text XML from Europe PMC on demand and summarize research focus, methods, findings, measurements and limitations side by side. Summaries combine selected sentences from the relevant article-body sections, including tables and figure captions; they are extractive, not AI paraphrases. Abstracts and reference lists are excluded. Each summary cites its source section. When full text or a section is unavailable, the app says so and does not fall back to the abstract. Transient lookup failures can be retried; unavailable provider coverage and access restrictions are distinguished from server errors. If automatic retrieval is unavailable, use **Import full text** in the comparison dialog to supply an article-body TXT file (up to 2 MB) or JATS XML file (up to 4 MB). TXT files need body section headings such as Introduction, Methods and Results. Imported files stay in browser memory and are labeled as user-provided; they are not independently verified. Abstracts, references and front matter are excluded from TXT imports. Nested XML sections retain their parent section context. Automatic full-text coverage is limited to articles available through Europe PMC; paywalls are not bypassed. These are reading aids, not quantitative scientific analysis. The former full-text questions section is removed. Statistical software is recorded as context, not executed. Relevance order comes from Crossref. Peer-review labels use DOAJ records matched to the journal ISSN: “Peer reviewed (journal policy)” describes the current journal policy, not article-level or historical verification. Editorial-only review and preprints have distinct labels; absent records or lookup errors display “Peer review unverified,” never a false negative. Registry requests are bounded to six seconds and four concurrent lookups per request; a registry outage does not block Crossref results. Review-article classification and exhaustive peer-review filtering are not supported. Arbitrary publisher URLs, PDF uploads and image graphs are not yet supported; use DOIs or doi.org URLs.

Organized findings and statistics remain in browser memory; search context and keywords are sent through the server to Crossref. There is no database, account, analytics or persistent experiment storage. Reloading clears the workspace. No credentials should be entered into the form.

## Development

Use feature branches and pull requests; keep main protected in repository settings. Add a failing behavioral test first, implement the change, then run tests and syntax checks before review. CI runs the same checks. Tests cover validation, metadata, comparison limits, HTTP/provider behavior and React interactions using deterministic fixtures. Browser tests cover desktop discovery, mobile DOI analysis, keyboard dialog dismissal, provider errors, review-policy provenance, and side-by-side comparisons with unavailable full text. Run `npm run test:e2e` after installing Chromium with `npx playwright install chromium`; use `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` when using a system browser. Live provider checks are separate from automated tests.

Before public deployment add rate limiting, operational monitoring and a privacy review. Semantic summaries, cross-study effect-size analysis and full-text sources outside Europe PMC require additional retrieval and analysis capabilities.

## GitHub Codespaces browser preview

Select the `main` branch on GitHub, then **Code → Codespaces → New with options** and choose a **2-core** machine. Confirm your personal account has remaining included usage before creating it. The dev container installs Node.js 24 dependencies, builds the frontend, starts the app on creation and resume, and forwards port 3000 privately. Open the **Ports** panel and choose **Open in Browser** for **Research Matching Tool** if the browser does not open automatically. Keep port visibility private.

Set the Codespace idle timeout to 15 minutes in GitHub settings. Stop it when finished; stopped Codespaces still use storage, so delete unused ones. GitHub Free personal accounts include 120 core-hours (about 60 running hours on a 2-core machine) and 15 GB-month storage monthly. Included quotas and billing depend on your account; see [GitHub's billing documentation](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-codespaces/about-billing-for-github-codespaces). Custom container images also consume storage allowance.

If startup fails, inspect `/tmp/research-matching-tool.log`, then run `bash .devcontainer/start.sh` from the repository. Rebuild changed frontend code with `npm run build`; refresh the preview after rebuilding.

For full-text diagnostics, `GET /api/health` reports `fullTextApiVersion: 2`. A 404 from `/api/full-text` means the running backend is outdated: pull main and rebuild/restart the Codespace container.
